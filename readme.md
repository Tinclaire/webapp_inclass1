### B2. 至少三段代表性 AI 對話

#### 對話 1

- ① 你遇到的問題：在 `renderTasks()` 裡想幫 `<li>`／`<span>`／`<button>` 加上 CSS 用的 class（例如 `task-item`、`completed`），寫了 `li.class = "..."` 卻完全沒有視覺效果。
- ② 你詢問 AI 的問題：「DOM 元素要設定 class 要用哪個屬性」
- ③ AI 的回答（摘要）：：DOM 元素沒有 `.class` 這個屬性（那是 HTML 的屬性名稱，不是 JS 物件上的屬性）；正確作法是 `.className`（字串，整個覆蓋，多個 class 用空白隔開）或 `.classList.add()/.remove()/.toggle()`（只操作單一 class，不會動到其他已存在的 class，比較安全、業界較常用）。
- ④ 你最後採取的做法：`<li>` 改用 `li.classList.add("task-item")`，並用 `if (task.completed)` 判斷要不要再 `classList.add("completed")`；`<span>`／`<button>` 因為只有單一固定的 class，改用 `.className` 直接賦值。
- ⑤ 是否修改 AI 的建議：沒有修改建議本身，但自己判斷在「固定 class + 條件式加成」的情境用 `classList`、在「單一固定 class」的情境用 `className`，是自己決定怎麼分配用哪一種寫法。

### 對話 2

- ① 你遇到的問題：`renderTasks()` 寫完後，按下「新增」按鈕，瀏覽器整個當掉，Console 出現 `Maximum call stack size exceeded`。當時的程式碼是 `span.click = toggleTask(task.id)`、`button.click = deleteTask(task.id)`。
- ② 你詢問 AI 的問題：詢問實作哪裡有問題
- ③ AI 的回答（摘要）：指出 `span.click = toggleTask(task.id)` 這種寫法後面加了括號，代表「立刻呼叫」函式，不是「註冊之後才觸發」的事件；因為 `toggleTask` 裡又呼叫了 `renderTasks()`，而 `renderTasks()` 執行到同一行又會立刻呼叫 `toggleTask`，兩者互相呼叫、沒有終止條件，造成無窮遞迴，最後堆疊溢出當機。
- ④ 你最後採取的做法：把 `span.click = toggleTask(task.id)` 改成 `span.addEventListener('click', () => { toggleTask(task.id) })`，`button` 也用同樣方式處理，測試後不再當機。
- ⑤ 是否修改 AI 的建議：AI 並沒有直接給修改後的程式碼，只解釋了問題發生的機制和方向；實際 `addEventListener` 的語法和寫法是自己動手寫、自己測試確認可以動了。

### 對話 3

- ① 你遇到的問題：原本用 `<span>` 綁 click 事件來模擬「點擊切換完成」，但覺得畫面上看不出勾選的樣子，跟老師範例的「□／☑」不太像，想改成真正的 `<input type="checkbox">`
- ② 你詢問 AI 的問題：「如何改寫成 checkbox」
- ③ AI 的回答（摘要）：建立 `<input type="checkbox">` 後，記得渲染時要把 `checkbox.checked` 設成 `task.completed`，不然每次 `renderTasks()` 重畫都會跳回未勾選；事件建議監聽 `'change'`（比 `'click'` 更符合 checkbox 的語意，鍵盤操作也比較穩）。
- ④ 你最後採取的做法：建立 `<input type="checkbox">`，渲染時設定 `checkbox.checked = task.completed` 讓畫面跟資料同步，並監聽 `'change'` 事件呼叫 `toggleTask(task.id)`；checkbox 放在 `<span class="task-text">` 前面。決定只留 checkbox 負責切換完成狀態，把 `<span>` 原本的 click 事件整個拿掉，文字本身不能再點擊切換。
- ⑤ 是否修改 AI 的建議：沒有修改，checkbox 的建立方式、`checked` 同步、監聽 `change` 都照 AI 說明的做；「文字要不要也能點擊切換」這個留給我自己決定的部分，我選擇不留，只用 checkbox 一個入口切換，介面比較單一、不會讓使用者搞不清楚該點哪裡。

## B4. 請說明一個你沒有直接採用 AI 建議的例子

AI 建議在 `renderTasks()` 中如果刪除按鈕是放在 `<li>` 裡面，而 `<li>` 本身也綁了 click 事件來切換完成狀態，刪除按鈕的 click 事件要記得呼叫 `event.stopPropagation()`，否則點刪除會同時觸發切換完成。

但我最後的實作方式是：`<li>` 本身完全沒有綁定 click 事件，而是分別在 `<span class="task-text">` 和 `<button class="delete-btn">` 上各自獨立綁定 `addEventListener('click', ...)`。
因為 `<li>` 沒有監聽 click，所以點擊刪除按鈕不會有「同時觸發切換完成」的問題，也就不需要 `stopPropagation()`。
原因是：我覺得讓文字跟刪除按鈕各自負責自己的點擊行為，邏輯上比較清楚，也比多加一行 `stopPropagation()` 更直覺。
